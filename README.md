# secrets/ — модель секретов

Этот репозиторий отвечает за жизненный цикл секретов: создание/ротацию
облачных секретов в Yandex Cloud, внешних секретов (GitHub), хранение в
зашифрованном виде через `pass` (passwordstore.org) с синхронизацией в S3,
и выпуск персональных GPG-ключей под каждую VM с локального мастер-ключа.

## Модель, по шагам

1. **Password-store** — git-репозиторий зашифрованных GPG-блобов,
   синхронизируется с S3 как remote. Можно хранить постоянно: содержимое
   зашифровано.
2. **Мастер GPG-ключ** — живёт только на текущей локальной машине
   пользователя, никогда не копируется ни на одну VM. См. `gpg/master/`.
3. **VM-ключ** — мастер-ключ выпускает отдельный GPG-ключ под конкретную VM
   (`gpg/master/issue-vm-key.sh`), который затем доставляется на неё вручную
   (`gpg/delivery/first-bootstrap.md`) — до этого момента VM физически не
   может расшифровать pass-store из S3.
4. **Облачные секреты (Yandex Cloud)** — ADM уже работает под admin service
   account, поэтому `providers/yandex_cloud/create-secrets.sh` использует
   этот `yc`, чтобы создавать/ротировать *другие* секреты (S3 static keys,
   SA-ключи для k8s workloads), и кладёт их в pass.
5. **Внешние секреты (GitHub)** — `external/github/`, тот же интерфейс
   создания/обновления.
6. **Сессия** — расшифрованные секреты живут только в `gpg-agent`/
   `ssh-agent` (память) и в tmpfs runtime dir на ADM; ничего не остаётся на
   диске после закрытия сессии.

## Конвенция путей в pass-store

- Облачные секреты: `providers/<provider>/<kind>/<name>`
  (например `providers/yandex_cloud/s3/pass-store-access-key`).
- Внешние секреты: `external/<system>/<name>`
  (например `external/github/deploy-key`).

Каждый источник секретов (провайдер или внешняя система) обязан иметь и
создание, и обновление/ротацию через один и тот же интерфейс — не только
первичное создание.

## Структура

```
secrets/
├── Makefile                  # gpg (local-only) / secrets (на текущей машине исполнения)
├── gpg/
│   ├── master/                # ТОЛЬКО локально — генерация/выпуск VM-ключей
│   └── delivery/               # ручная доставка VM-ключа на VM
├── providers/
│   └── yandex_cloud/           # create/update секретов в Yandex Cloud
└── external/
    └── github/                 # выпуск/обновление deploy-key или PAT
```

## Makefile

`make secrets` создаёт/ротирует облачные и внешние секреты на той машине,
где был вызван (без ssh-проброса — см. `AGENTS.md`). `make gpg-issue-vm-key
VM=<id>` — локальный таргет для выпуска ключа под конкретную VM. Оба типа
целей спрашивают подтверждение, если не задана переменная
`GANIEVRF_MAKE_ASK_SKIP=yes`.

Подробности — в `AGENTS.md` и в `../docs/secrets-flow.md`.
